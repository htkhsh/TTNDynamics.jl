# Holstein: 重み付き切断と浴の木の比較

10サイト・split・局在初期状態から0–1 fsで、切断方式と木の変更を分けて比較する。
Brownian周波数800、hopping 400、再配置エネルギー800、減衰300 cm⁻¹、300 K。
PSD order 0、各サイト2モード、階層局所サイズ5。50 fsの既存出力は変更しない。

実行コードと手順は [holstein_weighted_tree](../benchmarks/holstein_weighted_tree/README.md)。
両BUG手法でh=0.1 fs、atol=10⁻⁶、最大ランク64、局所Krylov許容誤差10⁻¹²を固定する。
Julia 1.12.6、8 workers、BLAS 1 thread。tAMEnはBLAS 8 threads。
CPUはAMD Ryzen Threadripper PRO 9985WX。
トレース方向を保護し、事後のトレース補正は使わない。
各ケースはwarm-up後に2回走らせ、伝播時間の中央値と範囲を記録する。
モデル構築・warm-up・観測・保存・誤差計算は伝播時間から除く。

## 変更内容

`truncate!(...; weighting=:weighted)` は、親側の相補空間の振幅を薄いQRで
小行列にまとめ、各枝の切断SVDに反映する。Gram行列を作って条件数を二乗しない。
保存量の部分木方向は従来どおり切断候補から除く。
各枝の予算は `atol / 枝数`。他の部分木で後から加わる直交射影は残差ノルムを
増やさないので、保存した相補因子から求める尾部ノルムは誤差上界として使える。
`discarded_bound` はその和で、丸め誤差と時間積分誤差は含まない。

従来方式は局所コアのSVDにルートノルムによる増幅上界を掛ける。
これは保守的な切断方式であり、重み付き方式は振幅の小さい方向をより早く落とす狙いがある。
この測定後、`truncation=:weighted` をaugmented / parallel BUGとadaptiveの既定値にした。
固定・adaptiveの `heom_evolve` / `tfd_evolve` からも指定できる。
従来方式は `truncation=:local`（単独の切断は `weighting=:local`）で選ぶ。
下記の測定では各方式を明示指定しており、既定値変更前の結果をそのまま残している。

`heom_tree(system; bath_grouping=:coupling)` は、結合演算子が厳密に一致する
モードを同じ部分木にまとめる。今回のHolsteinでは各サイトのBrownianの2成分が
兄弟になる。系のket/braの枝、物理軸順序、生成子は同じ。既定の `:balanced` は従来どおり。

**今回の条件では①単独が有効。** 従来比でaugmentedは31.1倍、parallelは22.0倍速い。
累積割当量もaugmentedで25.26→1.40 GiB、parallelで37.13→1.93 GiBへ減少した。
これはピーク使用メモリではない。最大局所ODE次元はそれぞれ835,584→56,376、
262,144→28,520へ減り、後続ステップの負担が軽くなっている。
切断誤差上界が予算内に収まらなかったステップ数は、両手法とも従来4/10から①で0/10になった。
この判定は切断の上界に対するものであり、時間発展全体の誤差保証ではない。

②単独はparallelで約1.15倍の短縮にとどまり、augmentedでは約1.20倍遅くなった。
①＋②も①単独より遅い。サイトの2成分を兄弟にしても全体の枝ランクが下がるとは限らず、
今回は①＋②のaugmentedで最大ランク56が必要だった。今後の長時間評価には、まず
**従来の木＋重み付き切断**を使うのがよい。

①で全状態の誤差は増えていない。parallelの密度行列誤差は約0.5%増えるが、元と同程度。
全ケースの最大トレース誤差は1.5×10⁻¹⁴未満だった。

tAMEn（h=0.5 fs、tol=10⁻⁴）は0.229 s、全状態差8.14×10⁻⁵、密度行列差8.90×10⁻⁶。

両者の全状態差は2.21×10⁻⁶、密度行列差は1.35×10⁻⁷だった。

## 検証

- TTNSolver：832項目通過。重み付き切断の複素数誤差上界、保存量、ゼロ状態、
  振幅スケーリング、ランク上限、両BUG手法の直列・スレッド実行を含む。
- TTNDynamics：459項目通過。同一結合モードが交互に並ぶ場合も物理軸を維持し、
  初期状態・生成子作用・トレースが一致することを確認。
- 既存の段階別計時コードも新しいキーワードに対応。計時付きのaugmented / parallel
  が通常実装と一致し、旧parallelソースの計測も維持されることを12項目で確認。
- 小系の密行列積分テストでは `enrich_basis(x, apply(op,x))` を使い、初期積状態で
  結合方向が局所方程式から見えない既存の制約を分離した。ベンチマークの局在初期状態には
  この追加処理を使わず、すべてのケースで同じ条件から開始する。
- 独立レビューで誤差上界と複素共役を確認。ランク2の保存量を持つ複素状態9例でも検証済み。

ソース変更後に旧50 fsチェックポイントを再開すると、既存のソース一致検査が拒否する。
新しい方式の計算は新しい出力先で行い、異なる実装の結果を混在させない。
